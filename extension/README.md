# AI Bro

Браузерное расширение (Manifest V3) для Chrome и Edge. AI Bro живёт в боковой панели:
читает открытую страницу, разбирает письмо в Gmail, Outlook Web или Яндекс Почте, предлагает варианты
ответа, постепенно подстраивается под ваш стиль и понимает голосовой ввод.

> Ключевой принцип: **расширение не отправляет письма само**. Оно только предлагает текст, а вставку в
> композер и отправку делает пользователь. Всё содержимое страниц и писем считается недоверенным
> (защита от prompt injection).

Прежнее рабочее имя — «Почерк»; данные и настройки пользователя не меняются.

Версия: **0.2.13** (`minimum_chrome_version` 114). Обработка — DeepSeek (`deepseek-flash`), ключ добавляет пользователь.

## Что уже работает

- **Боковая панель** с историей чатов, стримингом ответа, копированием и вставкой. Кнопка отправки
  вопроса называется **«Спросить»** — она не отправляет письмо; Enter — спросить, Shift+Enter — новая строка.
- **«Объяснить страницу»** — эвристическое извлечение основного текста (Readability-подобное, без библиотек).
- **«Ответить на письмо»** — чтение открытого треда Gmail / Outlook Web / Яндекс Почты, 3 варианта разного
  тона, вставка в композер (несколько стратегий + деградация до копирования в буфер).
- **«Краткая сводка»** — 3–5 коротких пунктов по открытому письму (суть, что хотят, сроки, действия).
- **«Разобрать письмо»** — подробный разбор только открытого письма: суть, требования, сроки, действия,
  чего не хватает.
- **Плавающая кнопка «AI Bro»** на страницах почты (Shadow DOM, не ломает вёрстку; переустанавливается при
  SPA-навигации).
- **Контекстное меню** «Спросить AI про выделенное» + «AI Bro: разобрать страницу».
- **Горячая клавиша** `Ctrl+Shift+Y` (`Cmd+Shift+Y` на macOS) открывает панель.
- **DeepSeek flash** (модель зафиксирована): reasoning среднего уровня, стриминг, проверка соединения.
- **Контекст**: всегда открытое письмо из reading pane; кнопки «Ответить на письмо», «Краткая сводка»,
  «Разобрать письмо», «Разобрать всю доступную переписку»; вложения (имена) в промпте, пометка пересылаемого
  письма, инструкция.
- **Профиль стиля**: формальность, длина, эмодзи, обращение, подпись + обучение на ваших правках
  (пары «черновик → финальный текст» хранятся локально, правила выводятся локально).
- **Голосовой ввод** через Web Speech API: кнопка микрофона, язык `ru-RU` по умолчанию, автостоп по тишине.
- **Демо-режим без ключа**: ответы генерируются локально из реального контекста; дисклеймер показывается
  отдельным notice в панели и не попадает в тело письма.

## Установка (unpacked)

### Chrome

1. Откройте `chrome://extensions`.
2. Включите **Developer mode** (Режим разработчика).
3. **Load unpacked** (Загрузить распакованное расширение).
4. Выберите папку `browser-ai-copilot\extension` (в ней лежит `manifest.json`).
5. Закрепите «AI Bro» на панели инструментов; сочетание клавиш меняется на `chrome://extensions/shortcuts`.

### Edge

1. Откройте `edge://extensions`.
2. Включите **Developer mode**.
3. **Load unpacked** → та же папка `extension`.
4. Панель: иконка расширения → **Открыть боковую панель** (Side panel) или `Ctrl+Shift+Y`.

Обновление после правок: кнопка «Обновить» на `chrome://extensions` / `edge://extensions`.

### Точная команда загрузки

- Chrome: `chrome://extensions` → Developer mode → Load unpacked → `<путь>\browser-ai-copilot\extension`
- Edge: `edge://extensions` → Developer mode → Load unpacked → `<путь>\browser-ai-copilot\extension`

Проверка манифеста без ручной загрузки (Windows):

```powershell
# сборка dist\aibro-0.2.13.zip + проверка ссылок манифеста
powershell -ExecutionPolicy Bypass -File .\extension\package.ps1

# Chrome/Edge: упаковка расширения (валидирует manifest и все файлы)
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" --pack-extension="$PWD\browser-ai-copilot\extension"
```

## Настройка: API-ключ

1. Создайте ключ в кабинете DeepSeek: <https://platform.deepseek.com/api_keys>.
2. Иконка «AI Bro» → **Настройки** (или `chrome://extensions` → Details → Extension options).
3. Вставьте ключ в единственное поле → **«Проверить соединение»** → **«Сохранить»**.
4. Пока ключа нет — работает демо-режим. При первом запросе браузер спросит доступ к `api.deepseek.com`.

Провайдер, адрес и модель зафиксированы в коде: **`deepseek-flash`** на `https://api.deepseek.com`,
reasoning среднего уровня (`thinking: enabled`, `reasoning_effort: "medium"`). Выбрать другую модель,
провайдера или Base URL в интерфейсе нельзя — в настройках есть только ключ, проверка соединения и
стриминг (в блоке «Дополнительно»). Температура не вынесена в UI: в режиме рассуждений DeepSeek её
игнорирует, а задачи используют собственные проверенные значения.

- **Проверить с реальным ключом:** `GET /models` (наличие `deepseek-flash`), приём `thinking` и
  `reasoning_effort`, SSE-стрим, ошибка 402 при нулевом балансе (в UI — только текст ошибки, без баланса
  и количества моделей). Если модели нет в списке — проверка соединения честно показывает ошибку; живой
  прогон генерации с ключом обязателен (в CI без ключа он недоступен).
- **Стриминг** — SSE в OpenAI-формате (`choices[0].delta.content`).

## Открытое письмо и вся доступная переписка

Панель всегда читает **область чтения** (reading pane) открытого письма и не использует `document.body`,
списки или сайдбары. Отдельного выбора сообщения/контекста больше нет.

- **«Краткая сводка»** — 3–5 сжатых пунктов только по открытому письму (без подробного разбора).
- **«Разобрать письмо»** и **«Ответить на письмо»** — работают только с **открытым письмом**: его тело
  (`openMessage`), отправитель, время, вложения.
- **«Разобрать всю переписку»** — работают все сообщения, реально отрисованные/развёрнутые в reading pane
  (`threadMessages`, открытое письмо включено). Сайдбар «Письма на тему», списки и свёрнутые сообщения не
  включаются. Если доступно одно письмо — панель честно пишет «В переписке доступен 1 фрагмент; чтобы
  учесть всю цепочку, нажмите „Открыть всю переписку“ и повторите».
- **Сообщения ниже вьюпорта** читаются, если они уже отрисованы в DOM reading pane (не важно, видно их
  на экране или нет). Свёрнутые «Предыдущее письмо» и лениво подгружаемые — только после «Открыть всю
  переписку»/прокрутки; автоматически разворачивать цепочку расширение не пытается.

Перед действием панель перечитывает открытое письмо (`GET_MAIL`). Если перечитать не удалось, ответ не
генерируется по устаревшему контексту — панель просит обновить страницу/панель. Перед вставкой сверяются
тема и отправитель/время открытого письма; если тема пустая/degraded — предупреждение и копирование в
буфер вместо автовставки. `MAIL_CONTEXT_CHANGED` (debounce 1.5 с) обновляет контекст при SPA-смене письма.

**Вложения** собираются с плашек файлов (`.mail-Message-Attachments`, `[class*="Attachment"]`, `.aZo`,
`[data-automationid*="attachment"]` и generic-эвристики по расширениям) только из области чтения и попадают
в промпт строкой `Вложения: имя1, имя2`. Письмо без текста, но с вложением, не теряется: в промпте —
«(без текста, см. вложения)». Содержимое вложений не читается; модели запрещено утверждать, что вложений
нет, если они перечислены, и выдумывать имена файлов.

**Пересылаемое сообщение** (`------ Пересылаемое сообщение ------`) остаётся частью верхнего письма, но в
промпте помечается как цитата вложенного письма.

**Имена не выдумываются.** Имя адресата — только из «От:/Кому:» открытого письма, иначе нейтральное
приветствие без имени; имена файлов — только из «Вложения:», нельзя склеивать тему письма с расширением.
В reply-задачу передаются строки `Адресат: …` и `Вложения (только эти имена): …`.

- **Инструкция к ответам** (необязательно, до 500 символов) — например: «отвечай кратко, от имени
  руководителя, без канцелярита». Добавляется в промпт как пожелание пользователя.

Из тела открытого письма вырезаются цитаты (`blockquote`, вложенные `.mail-Message-Body`/`.mail-Message`,
шапки «… пишет:»), поэтому вопросы из цитаты не попадают в контекст.
## Яндекс Почта и Яндекс 360 (mail.yandex.*, mail.360.yandex.*)

Поддержка включена по умолчанию: 16 яндекс-доменов прописаны в `manifest.json` → `content_scripts`
(итого 20 доменов почты вместе с Gmail/Outlook), никаких дополнительных разрешений и настроек не нужно.
Поддерживаются зеркала потребительской Почты (`mail.yandex.ru|com|by|kz|com.tr|az|co.il|ua`) и
**Яндекс 360 для бизнеса** (`mail.360.yandex.ru|com|by|kz|com.tr|az|co.il|ua`) с классическим BEM-UI.

**Что работает:**

- плавающая кнопка «AI Bro» в правом нижнем углу (не перекрывает «Написать»), переустанавливается при
  SPA-переходах «список → письмо»;
- контекстное меню и `Ctrl+Shift+Y`;
- чтение треда **best-effort**: тема письма, отправители/время из карточек, текст последних сообщений;
- «Ответить на письмо» — 3 варианта ответа, вставка в композер (contenteditable/textarea); «Краткая сводка» — 3–5 сжатых пунктов.
  «Вставить в письмо» есть у каждого варианта; вставляется ровно один выбранный вариант, без склейки всех трёх;
  деградация до копирования в буфер, если композер не найден или находится внутри iframe;
- извлечение текста обычной страницы, если открыть панель на любой вкладке.

**Два разных UI.** В потребительской Почте современный React-UI с хешированными CSS-модулями; в
**Яндекс 360** — классическая BEM-вёрстка (`.mail-Message`, `.mail-Thread-Subject`,
`.mail-Message-Sender`, `.mail-Message-Date`, `.mail-Message-Body`). Адаптер сначала определяет **область
чтения открытого письма** (`.mail-MessageView`/`.mail-Thread`/`.mail-Content` → `[role="main"]`), не используя
`document.body` и весь layout. Сайдбары и списки (`.mail-ThreadsList`, `.mail-MessageList`, `[class*="Sidebar"]`,
`[class*="Snippet"]`, `[class*="related"]`, `[role="complementary"]` и т.п.) исключаются полностью: их карточки
не попадают ни в `openMessage`/`threadMessages`, ни в `attachments`, ни в тему/участников. Внутри области
чтения BEM-карточки с телом отбираются, сниппеты отбрасываются; `openMessage` — открытое/развёрнутое/самое
свежее письмо, `threadMessages` — все реально отрисованные сообщения reading pane. При неполном распознавании
ставится `degraded` — модель получает пометку, что извлечение неполное, и не должна додумывать данные. На
логин-экране адаптер не отдаёт форму как «письмо» (`NOT_WEBMAIL`).

**Что проверить на реальном аккаунте (без него не проверялось):**

1. Войти в `mail.yandex.ru` и отдельно в `mail.360.yandex.ru`, открыть конкретное письмо.
2. Открыть письмо с правым сайдбаром «Письма на тему»: панель должна читать только открытое письмо (Скубба Антон); Никита Ганин/превью из сайдбара не должны появляться ни в контексте, ни во вложениях; кнопок анализа две — «Разобрать письмо» и «Разобрать всю переписку».
3. «Разобрать всю переписку» при раскрытой цепочке — все сообщения reading pane; при свёрнутой — пометка «В переписке доступен 1 фрагмент…».
4. Убедиться, что плавающая кнопка есть и не перекрывает «Написать»; проверить вход/выход из панели.
5. «Ответить на письмо»: правильная тема, отправитель, тело открытого письма в контексте; кнопки активны.
6. Письмо с вложением `.xls`: в ответе/сводке вложения перечислены (`Вложения: …`), нет фразы «вложений нет»; имена не из сайдбара.
7. Пересылаемое письмо (`------ Пересылаемое сообщение ------`) не путается с текущим: модель не приписывает его подпись/адресата верхнему письму.
8. Нажать «Ответить» → «Вставить в письмо» → текст попал в редактор (`.mail-Compose-Body`).
9. Если композер в iframe или не найден — проверить fallback «скопировано в буфер, вставьте вручную».
10. Длинный тред (5+ сообщений) и письма с вложениями/картинками; сниппеты списка не должны попадать в контекст.
11. SPA-переходы: список → письмо → следующий → «Написать»; кнопка не должна исчезать/дублироваться.
12. Языки интерфейса (ядро и зеркала) и тёмная тема.
13. На логин-экране (при выходе из аккаунта) — не должно быть ошибок в консоли и ложных «писем».

Проверялось без живого аккаунта: на синтетическом DOM с реальным `content.js` для обоих UI (BEM-карточки
`.mail-Message` и `data-testid`-карточки; тема, отправители/время, отсутствие сниппетов) и на публичной
странице `mail.yandex.ru`. Автоматически внедрить content-скрипт в эту сборку Chrome нельзя:
`--load-extension` в branded-Chrome отключён, поэтому injection и вставка в композер требуют ручной
проверки после «Load unpacked».

## Gmail и Outlook Web

То же поведение: плавающая кнопка, чтение открытого треда, 3 варианта ответа, вставка в композер.
Селекторы тоже эвристические и могут отставать от вёрстки — при поломке используется копирование в буфер.
Gmail API и Microsoft Graph не используются: их OAuth-скоупы (особенно Gmail restricted scopes → security
assessment) вынесены на этап беты, см. `proposals\engineering\architecture.md`.

## Как пользоваться

1. Откройте страницу или письмо (Gmail / Outlook / Яндекс Почта).
2. `Ctrl+Shift+Y` (или иконка) → боковая панель.
3. «Объяснить страницу» / «Ответить на письмо» / «Краткая сводка» / «Разобрать письмо» или свободный вопрос в поле ввода.
4. Нажмите **«Вставить в письмо»** — текст попадёт в открытый композер.
5. Поправьте текст и нажмите **«Учиться на правке»** — AI Bro запомнит разницу и подстроится.
6. Отправляет письмо всегда пользователь. Автоотправки нет ни в одной ветке кода.

## Приватность и безопасность

- **Что уходит в DeepSeek:** ваш вопрос, извлечённый текст страницы/письма (с лимитом символов) и
  профиль стиля. Для DeepSeek — на `api.deepseek.com/chat/completions`. Больше — ничего.
- **Где хранятся данные:** `chrome.storage.local`. Ключ и история чатов не синхронизируются.
- **Prompt injection:** текст страниц и писем оборачивается в блок с одноразовым nonce и явно
  помечается как недоверенные данные; модели запрещено выполнять инструкции из них и что-либо
  отправлять. Подозрительные инструкции в письме модель должна упомянуть в ответе.
- **XSS:** ответ модели рендерится только через DOM API (`textContent`), ссылки — с
  `rel="noopener noreferrer"`, никакого `innerHTML` из модели.
- **Нет remote code:** только локальные скрипты, без CDN. CSP: `script-src 'self'; object-src 'self'`.
- **Разрешения:** `activeTab` + `scripting` + опциональные хосты; на почту — 20 доменов декларативным
  контент-скриптом (для плавающей кнопки), `api.deepseek.com` запрашивается опционально при подключении.
- **Голос:** Web Speech API обрабатывает аудио облачным сервисом браузера (Google в Chrome,
  Microsoft в Edge). Расширение не получает и не хранит аудио; голос можно выключить в настройках.

## Известные ограничения

- **DOM-интеграция с почтой хрупкая.** Gmail, Outlook Web и Яндекс Почта меняют вёрстку без предупреждения:
  используются запасные селекторы, «упрощённое чтение» и флаг `degraded`; при неудаче — копирование в буфер.
  Для Яндекс Почты адаптер особенно эвристический (CSS-модули с хешами) — нужен QA на реальном аккаунте.
- Содержимое внутри **iframe** (в т.ч. композер ответа в модалке Яндекс Почты), **PDF-вьювер**, `chrome://`,
  `edge://`, Chrome Web Store, canvas-текст не читаются и не заполняются.
- Длинные страницы обрезаются (14 000 символов) и не чанкуются в MVP.
- Подписи и цитаты писем могут попадать в контекст или отбрасываться — эвристика не идеальна.
- Голосовой ввод зависит от браузера и сети; при недоступности Web Speech API кнопка отключается.
- Панель не умеет «закрываться» программно (нет API); `Ctrl+Shift+Y` открывает её.
- Нет OAuth, серверной части и синхронизации настроек между устройствами.
- DeepSeek без реального ключа проверен только статически (endpoint/тело/парсер); нужен прогон с ключом.
