# Как выложить «Почерк» в Chrome Web Store (и Edge Add-ons)

Расширение: `extension/` · артефакт: `extension/dist/pocherk-0.2.12.zip` · версия 0.2.12
Репозиторий: <https://github.com/ganinnikita1/ai_ext>

> **Сначала важное.** В Chrome Web Store можно загрузить zip, но **нельзя** загрузить «распакованное расширение»
> и нельзя обновлять его вручную у пользователей. Поэтому: один раз подаём в магазин, дальше каждая новая
> версия — через кабинет разработчика (обновление прилетает пользователям автоматически).

## 1. Аккаунт разработчика Chrome Web Store

1. Открыть <https://chrome.google.com/webstore/devconsole>.
2. Войти в Google-аккаунт (лучше отдельный, не личный).
3. Принять соглашение разработчика и оплатить **$5** (разово, карта).
4. Подтвердить e-mail; включить двухфакторную аутентификацию, если попросят.
5. Заполнить профиль разработчика: имя/бренд, контактный e-mail, сайт (можно GitHub репозиторий).

> $5 — разовый сбор за аккаунт, не за расширение. Одно расширение = один листинг.

## 3. Создать листинг и загрузить zip

1. В кабинете: **New item** (Новый элемент).
2. Загрузить `pocherk-0.2.12.zip` (перетащить/выбрать).
3. Заполнить карточку (готовые тексты — `docs/store-listing.md`):
   - **Name** (≤45 символов): `Почерк — AI-ответы в почте`
   - **Summary** (≤132): краткое описание;
   - **Description**: подробное, без обещаний «отправляет за вас»;
   - **Category**: Productivity; **Language**: Russian;
   - **Store icon**: 128×128 (уже в zip, но в кабинете просят отдельно);
   - **Screenshots**: 1280×800, до 5 штук (`docs/store/screenshot-1-1280x800.png` и т.д.);
   - **Small promo tile** (440×280) — опционально, но улучшает карточку;
   - **Marquee** (1400×560) — опционально для витрины.
4. **Privacy practices** (обязательно):
   - **Single purpose**: «AI-помощник: готовит черновики ответов на письма в веб-почте и разбирает открытую страницу».
   - **Permission justification** — по каждому пункту (готовые формулировки в `docs/store-listing.md`).
   - **Data use**: отметить категории данных и цели; указать, что данные отправляются в **DeepSeek** для генерации; ключ и история хранятся локально; данные не продаются и не используются для рекламы; подтвердить **Limited Use**.
   - **Privacy policy URL** — публичная ссылка на политику (см. ниже).
   - **Remote code**: «No, I don't use remote code» (у нас всё локально).
5. **Distribution**: Public / Unlisted / Private; регионы; бесплатно.
6. **Submit for review**.

## 4. Privacy policy: где взять URL

Черновик: `docs/privacy-policy.md`. Варианты публикации:

1. **GitHub Pages (проще всего)**: залить файл в репозиторий, Settings → Pages → Source: `main` / folder `docs`; политика будет по адресу
   `https://ganinnikita1.github.io/ai_ext/privacy-policy.html` (после включения Pages и публикации; Markdown можно
   конвертировать в HTML или положить `privacy-policy.html`).
2. Любой ваш сайт/Notion/лендинг — главное, публичный HTTPS-URL, доступный без авторизации.

В политике обязательно: какие данные обрабатываются (содержимое писем/страниц, API-ключ, история, профиль стиля),
куда уходят (DeepSeek), что хранится локально, как удалить, отсутствие продажи данных/рекламы, контакт.

## 6. Ревью и типичные отказы

Срок: обычно **1–4 недели** (может быстрее). Причины отказа и что делать:

| Причина | Как избежать |
|---|---|
| Remote code / CDN | у нас CSP `script-src 'self'`, внешних скриптов нет — приложить пояснение в notes |
| Права шире, чем описано | каждое право объяснить; optional `https://*/*` — «чтение страницы по кнопке пользователя (activeTab/scripting), иначе никак» |
| Нет privacy policy / data-use disclosure | публичный URL + честные категории (content of emails/pages, authentication info/API key) |
| Single purpose violation | одна функция: AI-черновики для почты/страниц; убрать/не упоминать второстепенное |
| Несовпадение описания и функциональности | не писать «автоответы»; отправку делает человек |
| Не работает без аккаунта/ключа | есть демо-режим + в notes для ревьюера дать шаги (ключ не нужен для демо) |
| Скриншоты не того формата | 1280×800, без рамок ОС/браузера (наши — ок) |
| Недоступная страница политики | проверить URL в режиме инкогнито |

Если отказ — исправляете, поднимаете версию (`0.2.12` → `0.2.13` в следующем релизе), загружаете новый zip, отвечаете в треде ревью.
Можно запросить **Unlisted** для теста у 20 человек до публичного релиза.

## 7. Обновления

1. Правите код, поднимаете `version` в `manifest.json` (SemVer: 0.2.12 → 0.2.13).
2. Собираете zip.
3. В кабинете → ваш item → **Upload new package** → Submit.
4. После ревью обновление уходит пользователям автоматически (Chrome проверяет раз в несколько часов).
5. Держите старые zip/версии в `dist`/релизах — откат делается загрузкой предыдущей версии (CWS может потребовать
   повышения версии, поэтому «откат» = новая версия с исправлениями).

5. Edge также устанавливает расширения из Chrome Web Store, поэтому можно публиковать в оба магазина.
